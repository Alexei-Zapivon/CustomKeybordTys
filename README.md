# minikeys — бинды и макросы только для мини-клавиатуры (Windows 11)

Программа перехватывает нажатия **только одного физического устройства** —
вашей мини-клавиатуры — и заменяет их на действия: сочетания клавиш, текст,
запуск программ, команды, макросы. Основная клавиатура не затрагивается:
её нажатия даже не попадают в программу.

```
 Основная клавиатура ──► kbdclass ──► Interception ──────────────────────► Windows (как обычно)
                                            │  фильтр не стоит
 Мини-клавиатура ─────► kbdclass ──► Interception ──► minikeys ──(глушит «A»)
                                         фильтр стоит       └──► SendInput: Ctrl+Shift+M / запуск / текст
```

## Почему именно так: Python + драйвер Interception

Главное требование — различать устройства и **глушить** нажатия одного из них.
Это отсекает большинство популярных вариантов:

| Инструмент | Видит устройство? | Может заглушить нажатие только с него? | Вывод |
|---|---|---|---|
| AutoHotkey (обычный), Python `keyboard`, `pynput` | ❌ хук `WH_KEYBOARD_LL` не знает источник | ❌ | не подходит |
| `evdev` | — | — | только Linux |
| `hidapi` | ✅ | ❌ Windows монопольно держит клавиатуры, читать их отчёты нельзя, глушить — тем более | не подходит |
| Raw Input + хук (HidMacros, LuaMacros) | ✅ | ⚠️ по совпадению событий во времени, бывают промахи | ненадёжно |
| **Драйвер Interception** (+ AutoHotInterception или свой код) | ✅ Hardware ID | ✅ фильтр ставится на конкретное устройство | **надёжно** |
| Прошивка (QMK/VIA) | — | — | отличное дополнение, см. ниже |

**Interception** — подписанный драйвер-фильтр режима ядра. Он стоит под
Windows, видит, с какого устройства пришло нажатие, и может его забрать
себе. Популярная связка **AutoHotkey + AutoHotInterception** использует
этот же драйвер. Я взял **Python + прямой вызов `interception.dll` через
ctypes**, потому что:

- нет промежуточных слоёв (AHK → C#-обёртка → dll), весь код на виду (~1300 строк с комментариями);
- бинды хранятся в отдельном понятном файле `config.toml`, он **перечитывается на лету**;
- конфиг проверяется при загрузке: опечатка в имени клавиши — понятная ошибка, а не молчаливый сбой;
- фильтр ставится **только** на мини-клавиатуру → если программа зависнет или упадёт,
  основная клавиатура продолжит работать (а при закрытии драйвер сам снимает фильтр).

## Установка (один раз)

1. **Python 3.11+** с [python.org](https://www.python.org/downloads/windows/), при установке
   отметьте «Add python.exe to PATH». Сторонние библиотеки не нужны.
2. **Драйвер Interception**: скачайте `Interception.zip` со страницы
   [github.com/oblitum/Interception/releases](https://github.com/oblitum/Interception/releases)
   (v1.0.1), распакуйте, откройте **cmd от имени администратора** и выполните:
   ```
   cd "путь\к\Interception\command line installer"
   install-interception.exe /install
   ```
   **Перезагрузите компьютер.**
3. Из того же архива скопируйте `library\x64\interception.dll` в папку проекта:
   `CustomKeybordTys\lib\x64\interception.dll`.
4. Проверка: `python -m minikeys list` — должен вывести список клавиатур.

## Графический интерфейс (MiniKeys.pyw)

Бинды можно настраивать в окне, без правки файлов.

**Установка (один раз, после драйвера и DLL):**
```
python -m pip install PySide6
```
**Запуск:** двойной щелчок по **`MiniKeys.pyw`** (или `python -m minikeys.gui`, тогда в консоли будет виден лог).

- **⌨ Устройство** — список подключённых клавиатур; кнопка «Определить нажатием» сама выделит
  ту, на которой вы нажали клавишу. VID/PID вручную вписывать не нужно.
- **＋ Кнопка** — режим добавления: нажимайте кнопки на мини-клавиатуре, каждая новая появляется
  на поле. Бинды в этом режиме не срабатывают. Перетащите кнопки мышью так, как они стоят на
  устройстве (сетка примагничивает).
- **＋ Крутилка** — мастер из трёх шагов: повернуть влево → повернуть вправо → нажать
  (нажатие можно пропустить). Крутилка на поле — круг: левая половина = поворот влево,
  правая = вправо, центр = нажатие. Щелчок по нужной части открывает её настройку.
- **Щелчок по кнопке** — окно действия: сочетание клавиш (можно «⏺ Записать» с основной
  клавиатуры), мультимедиа, запуск программы/сайта, ввод текста, макрос, команда, удержание.
  Назначенное действие видно прямо на кнопке. Правый щелчок — переименовать/удалить.
- При нажатии физической кнопки её двойник на поле подсвечивается.
- Действие **«Показать / скрыть окно minikeys»**: кнопка мини-клавиатуры разворачивает окно
  из трея и выводит его вперёд, а если окно уже активно, прячет обратно. Второй экземпляр
  программы не запускается (не назначайте для этого «Запуск программы» с путём к minikeys.exe).
- **Крестик сворачивает в трей** — перехват продолжает работать. Выход — через значок в трее.
  Там же можно временно выключить перехват.
- Всё сохраняется автоматически в `profile.json` (профили, устройство, бинды, расположение
  кнопок, настройки). При первом запуске туда переносятся бинды из `config.toml`.
  Консольная версия читает этот же файл: `python -m minikeys run -c profile.json`
  (активный профиль) или `... -c profile.json -p Gaming` (конкретный).
- GUI и консольная версия одновременно не запускаются — второй экземпляр откажется стартовать.
- Чтобы бинды работали в окнах «от администратора», запускайте GUI тоже от администратора
  (или через автозапуск ниже — он даёт нужные права).

### Профили

Панель **«Профили»** слева: «＋ Новый профиль» (устройство и расположение кнопок берутся из
текущего, бинды пустые), «Сделать копию» (вместе с биндами), «Переименовать» (или двойной
щелчок), «Удалить». Щелчок по профилю сразу переключает бинды: перехватчик получает новый
профиль на лету, без перезапуска. Переключать профили можно и из меню значка в трее
(«Профиль»). В каждом профиле свой выбор устройства, так что профиль можно привязать и к
другой мини-клавиатуре.

### Автозагрузка и запуск свернутой

«⚙ Настройки»:
- **Запускать вместе с Windows.** Если программа сейчас запущена обычным образом, она
  прописывается в реестр (`HKCU\...\CurrentVersion\Run`) и при входе стартует без прав
  администратора. Если запущена **от имени администратора**, создаётся задание Планировщика
  с наивысшими правами: тогда бинды работают и в окнах, запущенных от администратора
  (Windows не запускает из реестра программы, которым нужны такие права). Путь берётся
  автоматически: `minikeys.exe` после сборки или `MiniKeys.pyw` при запуске из исходников.
  Если перенести программу в другую папку, путь в реестре поправится при следующем запуске.
- **Запускать свернутой.** Окно не показывается при старте, программа сразу уходит в трей.
  Открыть окно можно щелчком по значку.

### Discord, игры и F13-F24

Если программа не видит нажатий от minikeys (типичный пример: запись горячей клавиши в Discord):

- **Как теперь нажимаются клавиши.** Каждая клавиша отправляется отдельно: нажатие, удержание
  (по умолчанию 30 мс), отпускание, с короткими паузами между клавишами сочетания. Раньше всё
  сочетание уходило одним пакетом с нулевым удержанием, и Discord его не замечал. Клавиши
  отправляются аппаратными скан-кодами (`KEYEVENTF_SCANCODE`), как от настоящей клавиатуры.
  «⚙ Настройки» → «Длительность нажатия»: 10 / 30 / 50 / 100 мс (если программа всё ещё
  пропускает нажатия, попробуйте 50).
- **Свободные клавиши F13-F24.** В окне кнопки выберите действие «Discord / свободная клавиша
  (F13-F24)». Программа сама предложит первую не занятую клавишу и покажет, что нажать в Discord.
  Галочка «Удерживать» нужна для режима рации (Push-to-talk). Этих клавиш нет на обычной
  клавиатуре, поэтому они ни с чем не конфликтуют; так же их можно назначать в OBS и играх.
- **Права администратора.** Windows не пропускает нажатия из обычной программы в окна,
  запущенные от администратора. Поэтому при запуске без прав minikeys перезапускает себя с
  запросом UAC (отключается в «Настройках»: «Запрашивать права администратора при запуске»).
  Если в окне UAC нажать «Нет», программа работает дальше, а в строке состояния будет
  «без прав администратора».
- **Отправка через драйвер.** «⚙ Настройки» → «Отправка нажатий» → «Через драйвер, как
  настоящая клавиатура». Нажатия идут через Interception от имени вашей основной клавиатуры:
  для Windows они неотличимы от настоящих. Помогает в играх, которые игнорируют программный
  ввод, и работает в окнах администратора даже без прав. Текст и мультимедиа по-прежнему
  отправляются обычным способом.

### Две одинаковые мини-клавиатуры

Две клавиатуры одной модели имеют одинаковые VID/PID и одинаковый Hardware ID.

- **По умолчанию** профиль привязан к модели (`match = VID/PID`), поэтому перехватываются
  **обе**, и бинды работают на обеих одинаково. Зажатые клавиши учитываются для каждого
  устройства отдельно, так что одновременные нажатия на двух клавиатурах не мешают друг другу.
- **Разделить.** В окне «Устройство» при нескольких одинаковых клавиатурах появляется
  подсказка; выберите нужную строку (или «Определить нажатием») и поставьте галочку
  **«Только это устройство»**. Профиль запомнит номер устройства (`device_number`) и будет
  работать только на нём; вторая клавиатура будет печатать как обычно или получит свой профиль.
- **Ограничение.** Драйвер Interception сообщает только номер устройства (порядок
  подключения) и Hardware ID, но не Instance ID / путь USB-порта. Номер стабилен, пока
  клавиатуры подключены, и после перезагрузки обычно сохраняется, но при переподключении
  клавиатура получает новый номер. Тогда статус покажет «не найдена», и её нужно выбрать
  заново (нажатием, это пара секунд). Надёжно различать клавиатуры по USB-порту можно было бы,
  сопоставляя Interception с Raw Input, но это отдельная доработка.
- Совсем не различить (ни этой, ни любой другой программой) две клавиатуры, работающие через
  **один** беспроводной приёмник: для Windows это одно устройство.

**Как это устроено (почему окно не зависает):**
```
 GUI-поток (Qt): окно, поле, диалоги
     │  set_profile / set_mode / list_devices  (очередь команд)
     ▼
 Поток RemapService: цикл драйвера Interception ── Worker-поток: выполнение действий
     │  on_key / on_learned / on_probe / on_targets
     ▼
 ServiceBridge → Qt-сигналы (доставляются в GUI-поток через очередь событий)
```
Драйвер опрашивается только в потоке `RemapService` (`minikeys/service.py`); окно
лишь редактирует профиль и отправляет его сервису. Макрос с паузами выполняется в
отдельном потоке и не задерживает ни приём нажатий, ни интерфейс.

## Сборка minikeys.exe

Один файл `minikeys.exe`, который запускается без установленного Python и без окна консоли
(только окно программы и значок в трее).

**Что нужно на компьютере, где собираете:** Python 3.11+, этот проект и
`lib\x64\interception.dll` (из архива Interception: `library\x64\interception.dll`).

**Проще всего:** двойной щелчок по **`build.bat`**. Он поставит PyInstaller и PySide6 и соберёт
программу. Результат: **`dist\minikeys.exe`**.

**Вручную** (PowerShell в папке проекта):
```
python -m pip install --upgrade pyinstaller PySide6
python -m PyInstaller --noconfirm --clean minikeys.spec
```

Что задаёт `minikeys.spec`:
- `console=False`: windowed-приложение, чёрного окна консоли нет;
- один файл (onefile): всё, включая Qt и `interception.dll`, внутри `minikeys.exe`;
- иконка `assets\minikeys.ico` (пересоздать: `python tools\make_icon.py`) и версия в свойствах файла;
- `uac_admin=True` (то же, что ключ `--uac-admin`): exe всегда запускается с правами
  администратора, Windows показывает окно UAC при ручном запуске. Автозапуск при этом идёт
  через Планировщик заданий без окна UAC (галочка «Запускать вместе с Windows»).

**После сборки:**
- Положите `minikeys.exe` в любую папку, куда можно писать (например, `F:\minikeys\`).
  Профиль и лог будут рядом с exe (`profile.json`, `minikeys.log`). Если папка недоступна
  для записи (например, `Program Files`), они хранятся в `%APPDATA%\minikeys\`.
- Чтобы сохранить текущие бинды, скопируйте ваш `profile.json` рядом с `minikeys.exe`.
- **Драйвер Interception всё равно нужен** (установить один раз, см. «Установка»): exe содержит
  только `interception.dll`, а драйвер ставится в систему отдельно.
- Размер файла около 50–70 МБ (это Qt). Первый запуск на пару секунд дольше: exe распаковывается
  во временную папку.
- Антивирусы иногда ложно реагируют на программы, собранные PyInstaller. Если это случилось,
  добавьте файл в исключения. UPX-сжатие в сборке специально выключено, оно усиливает проблему.

## Как узнать ID мини-клавиатуры

**Способ 1 (рекомендую) — нажатием:**
```
python -m minikeys identify
```
Нажмите пару кнопок на мини-клавиатуре, потом на основной:
```
устройство №2  клавиша a              (скан-код 0x1E)  ID: HID\VID_046D&PID_C52B&REV_1211&MI_00
устройство №4  клавиша a              (скан-код 0x1E)  ID: HID\VID_1189&PID_8890&REV_0001&MI_00
устройство №4  клавиша numpad_add     (скан-код 0x4E)  ID: HID\VID_1189&PID_8890&REV_0001&MI_00
```
Строки мини-клавиатуры узнаются сразу. В `config.toml` в `[device]` впишите
часть ID `match = "VID_1189&PID_8890"`, а в `[binds]` — имена клавиш из
колонки «клавиша».

**Способ 2 — без драйвера** (PowerShell, показывает ещё и USB-порт):
```
powershell -ExecutionPolicy Bypass -File tools\list-keyboards.ps1
```
Запустите дважды — с подключённой мини-клавиатурой и без неё; пропавшая запись — она.

**Способ 3 — вручную:** Диспетчер устройств → Клавиатуры → (устройство) →
Свойства → Сведения → «ИД оборудования». Нужна часть `VID_xxxx&PID_yyyy`.

> **Про MAC-адрес и номер порта.** Для Bluetooth-клавиатур ID выглядит как
> `HID\{00001124-...}_VID&0002046D_PID&B35B` — подставьте в `match` кусок
> `VID&0002046D_PID&B35B`. Номер USB-порта драйвер не сообщает, поэтому
> привязка идёт по VID/PID — это надёжнее: клавиатура узнаётся в любом порту
> и после переподключения (программа ищет её каждые 2 секунды).

## Настройка биндов — `config.toml`

```toml
[device]
match = "VID_1189&PID_8890"

[settings]
unmapped = "block"   # неназначенные клавиши мини-клавиатуры: "block" — глушить, "pass" — пропускать
log_keys = true      # печатать нажатия (удобно при настройке)

[binds]
a = "ctrl+shift+m"                                   # сочетание (короткая форма)
q = { run = "notepad.exe" }                          # программа
w = { run = 'C:\Tools\app.exe', args = "--flag" }    # путь в '...' — слеши не удваивать
e = { run = "https://github.com" }                   # сайт, файл, папка
t = { cmd = 'ipconfig /flushdns' }                   # команда cmd.exe без окна
z = { text = "Привет!\n" }                           # текст любым языком, \n = Enter
numpad_add = { hotkey = "volume_up", repeat = true } # срабатывать и при удержании
space = { remap = "f13" }                            # кнопка ведёт себя как F13, пока зажата

[binds.v]                                            # макрос
macro = ["ctrl+a", "ctrl+c", { delay = 100 }, { run = "notepad.exe" }, { delay = 800 }, "ctrl+v"]
```

- Шаги макроса: строка-сочетание, `{ delay = мс }`, `{ text = ... }`, `{ run = ... }`,
  `{ cmd = ... }`, `{ click = "left"|"right"|"middle" }`, `{ down = "shift" }`, `{ up = "shift" }`.
- Имена клавиш: `a`–`z`, `0`–`9`, `f1`–`f24`, `numpad0`–`numpad9`, `numpad_add/sub/mul/div/dot/enter`,
  `enter esc space tab backspace delete insert home end page_up page_down up down left right`,
  `ctrl shift alt win` (и `rctrl ralt rshift rwin`), `volume_up volume_down volume_mute`,
  `media_play_pause media_next media_prev`, символы в кавычках: `"-" "=" "[" "/"`…
  Незнакомая клавиша: `sc_XX` / `sc_e0_XX` — как покажет `identify`.
- Сочетания не зависят от раскладки: `ctrl+shift+m` сработает и на русской.
- Файл перечитывается сам после сохранения. Ошибка в файле → в консоли
  сообщение, программа продолжает работать со старой версией.
- Проверить файл: `python -m minikeys check`.

## Запуск

```
python -m minikeys          (или двойной клик по run.bat)
```
Остановка — `Ctrl+C` в окне консоли.

**Права администратора.** Windows не даёт обычной программе нажимать клавиши
в окнах, запущенных от администратора (диспетчер задач, установщики, некоторые
игры). Если бинды там не работают — запускайте `run.bat` от администратора.

**Автозапуск при входе:** в GUI это галочка «Запускать вместе с Windows» (см. выше).
Для консольной версии или без GUI (с правами администратора, лог в `minikeys.log`)
в PowerShell от администратора:
```
powershell -ExecutionPolicy Bypass -File tools\autostart.ps1           # GUI, свёрнутый в трей
powershell -ExecutionPolicy Bypass -File tools\autostart.ps1 -Console  # консольная версия
powershell -ExecutionPolicy Bypass -File tools\autostart.ps1 -Remove   # выключить
```

## Совет: прошивка + minikeys

Если мини-клавиатура программируется (QMK/VIA/фирменная утилита), назначьте
её кнопкам **F13–F24** — их нет на обычной клавиатуре, и они никогда не
конфликтуют. А в minikeys привяжите к ним действия. Если прошивка шлёт
«мультимедийные» коды (громкость, play) или несколько клавиш сразу — лучше
переназначить их на обычные клавиши: мультимедиа-коды идут мимо драйвера
клавиатуры, Interception их не видит.

## Известные ограничения

- **Одинаковые VID/PID.** Если мини- и основная клавиатура подключены через один
  беспроводной приёмник (например, Logitech Unifying), для Windows это одно
  устройство — различить их невозможно никаким софтом. Подключайте мини-клавиатуру
  отдельно. Если у двух разных клавиатур совпали VID/PID, используйте `exclude`
  или `device_number` из вывода `identify` (номер может смениться после переподключения).
- **Лимит драйвера.** Известная особенность Interception: после многократного
  переподключения USB-устройств (≈10+ раз за сеанс) новые подключения перестают
  перехватываться до перезагрузки ПК.
- **Античиты.** Некоторые онлайн-игры с kernel-античитом (Vanguard, FACEIT и т.п.)
  могут отказываться запускаться при установленном Interception.
- Одновременно с другими программами на Interception (AutoHotInterception и т.п.)
  не запускайте — они будут делить одно устройство.
- `Win+L` и `Ctrl+Alt+Del` системой запрещено имитировать программно.

## Удаление

```
powershell -ExecutionPolicy Bypass -File tools\autostart.ps1 -Remove
install-interception.exe /uninstall     (cmd от администратора), затем перезагрузка
```

## Структура проекта

```
MiniKeys.pyw                запуск графического интерфейса двойным щелчком
profile.json                профили GUI и настройки (создаётся сам)
minikeys.spec, build.bat    сборка dist\minikeys.exe (PyInstaller)
assets/minikeys.ico         иконка exe (tools/make_icon.py)
config.toml                 бинды для консольной версии
run.bat                     запуск в консоли
minikeys/service.py         фоновый перехватчик (поток драйвера + очередь команд), общий для GUI и консоли
minikeys/store.py           profile.json: профили, загрузка/сохранение, раскладка кнопок и крутилок
minikeys/paths.py           пути к файлам в режиме исходников и собранного exe
minikeys/autostart.py       автозагрузка: реестр или Планировщик заданий
minikeys/elevation.py       права администратора: проверка и перезапуск с запросом UAC
minikeys/bindtext.py        подписи на кнопках, текстовый формат макросов
minikeys/gui/               интерфейс на PySide6: app.py (окно, трей, настройки), canvas.py (поле),
                            profiles.py (панель профилей), dialogs.py (действия, крутилки,
                            выбор устройства), bridge.py
minikeys/interception.py    обёртка над interception.dll (ctypes)
minikeys/engine.py          логика: какое нажатие глушить, что запускать, удержание/автоповтор
minikeys/actions.py         действия: сочетание, текст, запуск, команда, клик, макрос
minikeys/winput.py          вывод в Windows: скан-коды с удержанием (SendInput) или через драйвер
minikeys/keys.py            таблицы скан-кодов и виртуальных кодов, имена клавиш
minikeys/config.py          загрузка и проверка config.toml
tools/list-keyboards.ps1    список клавиатур с VID/PID и USB-портом (без драйвера)
tools/autostart.ps1         автозапуск через Планировщик заданий
tests/                      тесты: python -m unittest (GUI-тесты работают без экрана)
```
